# Ноутбуки

Два ноутбука отвечают на два разных вопроса. Первый — «покажите, что вы сделали и что
это ваш файл». Второй — «покажите работающее решение, собранное с нуля».

| Файл | Ячеек | Что делает | Сколько идёт |
|---|---:|---|---|
| `antifraud_solution.ipynb` | 57 | разведка, обучение двух моделей, сборка сабмита, сверка | ~50 мин |
| `e2e_solution.ipynb` | 48 | полный стек из 34 модулей, 18 стадий обучения | часы |

## antifraud_solution.ipynb

Первая ячейка — конфиг: пути, флаги прогона, параметры моделей и веса смешивания.
Дальше всё исполняется подряд, `Run All` работает.

| Раздел | Что происходит |
|---|---|
| 1. Данные | время, пропуски, структура V-колонок, восстановление скрытого пользователя |
| 2. Валидация | почему случайный KFold врёт и на чём проверяются решения |
| 3. Проверка гипотез | сырые `V` против свёрнутых, откуда взялись 30 избранных колонок |
| 4. Признаки | сборка 712 и 1046 признаков |
| 5. Модели | две LightGBM, важность признаков по семействам |
| 6. Рецепт смешивания | проверка весов на нетронутом временном фолде |
| 7. Ветка `end2end` | запуск полного стека из `src/end2end/` |
| 8. Ветка `byte2byte` | сборка того файла, который ушёл в лидерборд |
| 9. Сверка | что совпало с эталоном, что взято готовым |

Переключатели в первой ячейке:

```python
SOLUTION       = "byte2byte"   # или "end2end"
RUN_EDA        = True          # разделы 2-3, на результат не влияют
TRAIN_MODELS   = True          # False -> взять готовые веса или предсказания
VALIDATE_BLEND = True          # раздел 6
```

Разделы 2 и 3 — исследование: они обосновывают константы из конфига, но в сабмит
не входят и отключаются флагом. Кому нужна только воспроизводимость — разделы 4, 8 и 9.

### О точности воспроизведения

`TRAIN_MODELS = False` даёт побайтовое совпадение с отправленным файлом в любой среде:
модели не переобучаются, берутся готовые предсказания.

`TRAIN_MODELS = True` переобучает обе модели с нуля. В той же среде результат совпадает
до последнего бита; на другой машине — расходится в младших разрядах признаков и даёт
ROC AUC в пределах 1e-4 от исходного. Проверено: смена версии LightGBM результат
не меняет вовсе, расхождение появляется от арифметики с плавающей точкой на другом железе.

## e2e_solution.ipynb

Самостоятельное решение: обучает всё с нуля из пяти официальных CSV. Не читает ни меток
теста, ни прошлых сабмитов, ни готовых весов — ноутбук проверяет это статически по
исходникам перед запуском и сверяет sha256 всех пяти входных файлов.

Устройство: 34 модуля пишутся на диск через `%%writefile`, затем 18 стадий запускаются
подпроцессами. Каждая стадия изолирована, память освобождается между ними.

| Стадия | Что обучается |
|---|---|
| 1 | фундамент: CatBoost, LightGBM, XGBoost + нейронный стек по временным фолдам |
| 2 | отобранные V-block и структурные представления, клиентский мета-LightGBM |
| 3 | тяжёлый clean-v2 и XGB-magic с горизонт-зависимыми источниками |
| 4 | финальный клиент-профильный residual: 96 признаков сворачиваются в профиль клиента |

Отбор весов и формы моделей — на временных фолдах с эмбарго, последний фолд остаётся
замком. Test ROC AUC внутри не считается: единственная исполняемая метрика отбора —
временной замок на размеченном train.

Нужны `torch`, `catboost`, `xgboost`. На Kaggle предустановлены, локально ставятся
из `requirements.txt`.

## Запуск на Kaggle

1. Данные соревнования — через Add Input.
2. Код подтягивается `git clone` в первой ячейке, для этого нужен включённый Internet.
   Если интернет запрещён — приложите репозиторий вторым датасетом, ноутбук найдёт
   `src/pipeline.py` и там.
3. Первый заход стоит остановить после второй ячейки и убедиться, что пути найдены.
