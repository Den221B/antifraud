# Антифрод: обнаружение мошеннических транзакций

Предсказание `isFraud` для транзакции. Метрика — ROC AUC, то есть важен порядок строк
по риску, а не калибровка вероятностей.

Две особенности данных определили архитектуру:

1. train и test разделены во времени — случайный KFold завышает качество примерно на 0.07 AUC;
2. явного `user_id` нет, но его восстанавливает прокси-ключ `card1 + addr1 + origin_day + P_emaildomain`,
   где `origin_day = round(TransactionDT / 86400 - D1)`. Две трети test — пользователи,
   которых не было в train.

## Признаки

Собираются в два набора, обе модели — LightGBM с фиксированными параметрами:

| Набор | Признаков | Что входит |
|---|---:|---|
| `vblock` | 712 | построчные, профиль пользователя, поведение, свёрнутые V-блоки |
| `structured` | 1046 | то же плюс календарь, суммы, разбор устройства, распределения значений |

Сырые `V1–V339` выброшены: на временном фолде они проигрывают собственным сводкам
по блокам. 339 колонок дают всего полтора десятка разных долей пропусков — они
заполняются пачками, и каждая из 11 таких пачек сворачивается в 10 чисел.

## Финальная формула

База плюс два residual, подмешанных только «холодным» пользователям и с малыми весами:

```
final              = rank(base)
final[cold]        = 0.8875 * final[cold] + 0.1125 * rank(vblock_model)[cold]
final              = rank(final)
final[cold]        = 0.9750 * final[cold] + 0.0250 * rank(structured_model)[cold]
```

Веса зафиксированы временной валидацией до прогона. Они маленькие намеренно: обе модели
смотрят на те же данные, что и база, и их задача — переставить строки там, где база
не уверена, а не переголосовать её. На знакомых пользователях порядок не меняется вовсе.

## Запуск

```bash
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute --inplace notebooks/antifraud_solution.ipynb
```

Ветка выбирается константой `SOLUTION` в первой ячейке ноутбука, подробности —
в [notebooks/README.md](notebooks/README.md).

## Что берётся готовым

Базовый ансамбль исходного прогона — стек из 13 моделей с временной валидацией, поверх
него UID-consistency и сегментные residual. Пошагово его не восстановить: не сохранились
промежуточные артефакты.

Поэтому для точного повтора отправленного сабмита используются два готовых входа из
`models/byte2byte/`: предсказание базового ансамбля и сегментация test. Всё остальное —
признаки, обе модели, смешивание — считается из сырых данных.

Полностью самостоятельный вариант без этих входов — `notebooks/e2e_solution.ipynb`.
